Introduction to Agentic PKM

How structured knowledge makes AI agents useful
OptiFlows — March 2026
Bottom line: An agentic PKM is an Obsidian vault where every piece of knowledge is structured so that both you and an AI agent can find, read, and act on it. You do not need embeddings, vector databases, or ingestion pipelines. You need markdown files with consistent structure, wikilinks between them, and Claude Code pointed at the folder. The vault IS the database. The structure IS the retrieval system.
01 / THE PROBLEM WITH "BRAND MEMORY"

The problem with "Brand Memory"

Most companies have the same problem: brand messaging lives across too many places - strategy decks, campaign plans, website copy, sales materials, LinkedIn posts - and AI tools cannot reliably access it. The conventional approach is RAG (retrieval-augmented generation) - chunk your documents, embed them in a vector database, and retrieve by similarity. It works at scale. But for a company with 30-200 brand documents, there is a simpler architecture that gives you more control, deploys in hours instead of weeks, and has zero infrastructure to maintain.

The insight: structured markdown files with consistent formatting are already machine-readable. An AI agent does not need embeddings to find relevant content. It needs a folder of well-organised files with clear names, consistent frontmatter, and links between them. Claude Code can read any file, search any folder, and follow references between documents. The "retrieval" happens through file structure and naming, not vector similarity.

02 / WHAT IS A PKM

What is a PKM?

A personal knowledge management system (PKM) is a vault where knowledge moves through stages, from raw observations to actionable capabilities. Obsidian is the tool. The vault is the system.

explanation  -->  principle  -->  essay  -->  skill
  (atom)          (rule)        (playbook)   (capability)
The vault pipeline — knowledge progresses from atoms to capabilities

Each stage has a specific purpose:

  • Explanations are atomic knowledge nodes. One concept per file. "What is our brand positioning?" is one explanation. "What is our brand voice?" is another. Each stands alone.
  • Principles are actionable rules synthesised from explanations. "Always lead with reliability data when addressing enterprise prospects." or "Never use jargon without defining it in the next sentence."
  • Essays are operational playbooks that weave explanations and principles into coherent strategy. A messaging framework document. A campaign narrative guide. These are the documents your team currently has scattered across decks and drives.
  • Skills are Claude Code capabilities - instructions that let an AI agent execute a repeatable workflow using the knowledge in the vault.
03 / WHAT MAKES IT AGENTIC

What makes it "agentic"?

A regular PKM serves one user - the person who writes in it and reads from it. An agentic PKM serves two users: the human and the AI agent. The same vault, the same files, traversed by both.

How the human uses it

  • Obsidian's graph view shows relationships between concepts
  • Backlinks show what references what
  • Search finds content by keyword
  • Daily use builds familiarity and institutional memory

How the agent uses it

  • Frontmatter descriptions let the agent scan files without reading them fully - it reads the one-line description and decides whether to open the file
  • Wikilinks act as edges in the knowledge graph - the agent follows relevant paths and skips what does not matter
  • Consistent structure means the agent knows where to find what - definitions are always at the top, details are always in the notes section
  • Progressive disclosure - the agent reads index files first, then descriptions, then links, then sections, then full content. Most decisions happen before reading a single full file.
The key difference from RAG

A RAG system chunks your documents, converts them to vectors, and retrieves based on mathematical similarity. An agentic PKM keeps your documents whole and structured, and the agent navigates them the same way you do - by following links and reading headers. You maintain one set of files. No ingestion pipeline. No embeddings to regenerate when content changes. Edit a markdown file and the agent immediately sees the update.

04 / THE GRAPH

The graph

Every file is a node. Every link between files is an edge. Together they form a knowledge graph that captures not just what you know, but how concepts relate to each other.

Here is an example for a B2B company with technical products:

Node typeExampleLinks to
Explanationcore-product.mdbrand-voice.md, enterprise-positioning.md
Explanationbrand-voice.mdmessaging-pillars.md, tone-guidelines.md
Principlelead-with-reliability.mdcore-product.md, case-study-enterprise.md
Essaycampaign-narrative.mdcore-product.md, lead-with-reliability.md, enterprise-positioning.md
Skillgenerate-linkedin-post/brand-voice.md, messaging-pillars.md

When an agent needs to write a LinkedIn post about your core product, it does not do a vector search. It reads the generate-linkedin-post skill, which tells it to read brand-voice.md and messaging-pillars.md. Those files link to core-product.md and relevant case studies. The agent follows the graph to exactly the context it needs. No over-retrieval, no missed context, no hallucinated messaging.

05 / WHY THIS MATTERS

Why this matters

If your goal is "everything we generate becomes more consistent with our brand narrative," an agentic PKM delivers that directly. Here is why it is better than the vector database approach for companies with under 200 documents:

FactorVector DB (RAG)Agentic PKM
Setup timeDays to weeks (workflow automation, database schema, embedding pipeline)Hours (create Obsidian vault, add files)
Content updateEdit file, re-run ingestion, regenerate embeddingsEdit file. Done.
Retrieval qualityDepends on chunk size and embedding modelDepends on file structure and link quality
MaintenancePipeline monitoring, embedding model updates, database managementNone beyond writing and organising files
CostDatabase hosting, embedding API callsZero (local files + Claude Code)
Agent integrationCustom retrieval API neededPoint Claude Code at the folder
Human usabilityRequires frontend to queryObsidian - browse, search, graph view

With 30-50 documents, you are well within the range where structured files outperform embeddings. Vector databases shine at scale (thousands of documents) where no human could maintain a link structure. At 50 documents, you can maintain it manually and get better results.

06 / GETTING STARTED

Getting started

  1. Install Obsidian - free, works on Mac/Windows/Linux, stores everything as local markdown files
  2. Create a vault - one folder on your machine (or shared drive)
  3. Install Claude Code - Anthropic's CLI agent that can read and work with your vault
  4. Start writing - begin with your most important brand assets as individual markdown files with consistent frontmatter

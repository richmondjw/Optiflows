PART 03

Architecture - The Simplest Stack That Works

Section 8.0 - Three-Layer Operating Model

The architecture follows one principle: start simple, add complexity only when proven necessary. The research validates that production-grade content operations can be built on three layers without a vector database, RAG pipeline, or orchestration framework.

This is a deliberate choice. The failure rate in AI systems is not a technology problem - it is an architecture problem. 80% of multi-agent pilots fail within six months. 95% of generative AI pilots yield no business impact. The common thread is over-engineering: teams build complex systems before validating simple ones.

Architectural Design Principles

"Safety is architecture, not prompting." - An agent that cannot access a file is safer than an agent told not to access it.
"Design for failure, not success." - 44% of multi-agent failures are system design issues, not model issues.
"Curate memory, don't accumulate it." - Raw logs are noise, not knowledge. Strategic forgetting is a feature.
"Ship the simplest system that teaches you something." - One agent, one task, one real content piece will teach more than any amount of upfront architecture.

Section 8.1 - The Intelligence Layer

Every agent, every workflow, and every piece of AI-generated content in this system reads from the same place: the intelligence layer. If the intelligence layer is thin, generic, or poorly structured, everything downstream will be too. This is not a technical detail - it is the single most consequential architectural decision in the entire operating model.

The research is unambiguous on this point. The organisations that succeed with AI are the ones that invest in knowledge architecture first. In plain language: the intelligence layer is everything the AI needs to know to sound like 776BC and make decisions like 776BC.

Why the Intelligence Layer Is the Moat

Models are commoditised. GPT, Claude, Gemini - any brand can access the same AI capabilities. The technology is table stakes. What cannot be replicated is accumulated organisational knowledge, deliberately structured for AI consumption.

  1. It compounds. Every approved piece of content becomes a new exemplar. Over 12 months, a competitor starting from scratch would face thousands of curated knowledge artefacts they cannot replicate.
  2. It is brand-specific. A generic AI can write about rowing. Only an AI with 776BC's intelligence layer can write as 776BC.
  3. It improves every agent simultaneously. One knowledge update improves ten outputs.
  4. It survives technology changes. If a better AI model launches tomorrow, 776BC switches the model and keeps the intelligence layer.
  5. It turns knowledge into capability. The intelligence layer is not documentation - it is operationalisation.

How to Build It

  • Phase 2: Exemplar Curation (Week 2) - Kate and the team identify 15-20 gold standard content pieces. Each exemplar filed with metadata. Create per-platform guidelines. Consolidate competitive intelligence.

The Memory Promotion Pattern

Critical Design Rule

Only curated, validated knowledge gets promoted. The most common failure in AI knowledge management is treating accumulation as progress. Strategic forgetting - archiving or removing low-value content - is a feature, not a bug.

Evidence that model triage works at scale:

  • Anthropic's own benchmarks: Haiku achieves 90% of Sonnet's performance on agentic coding tasks.
  • RouteLLM (open-source model router): achieves 95% of GPT-4 quality while routing only 14% of calls to GPT-4.

  • PGA Tour: reduced article generation costs by 95% using model tiering and prompt caching.

776BC pilot approach: default to Sonnet as primary model for all agents and track where quality requires Opus and where Haiku would suffice.

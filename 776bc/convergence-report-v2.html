Section 8.0

Three-Layer Operating Model

The architecture follows one principle: start simple, add complexity only when proven necessary. The research validates that production-grade content operations can be built on three layers without a vector database, RAG pipeline, or orchestration framework.

This is a deliberate choice. The failure rate in AI systems is not a technology problem — it is an architecture problem. 80% of multi-agent pilots fail within six months. 95% of generative AI pilots yield no business impact. The common thread is over-engineering: teams build complex systems before validating simple ones. Four design principles, drawn from production agent deployments, govern every decision in this operating model.

Architectural Design Principles

“Safety is architecture, not prompting.” — An agent that cannot access a file is safer than an agent told not to access it.
“Design for failure, not success.” — 44% of multi-agent failures are system design issues, not model issues.
“Curate memory, don’t accumulate it.” — Raw logs are noise, not knowledge. Strategic forgetting is a feature.
“Ship the simplest system that teaches you something.” — One agent, one task, one real content piece will teach more than any amount of upfront architecture.

Section 8.1

The Intelligence Layer

Every agent, every workflow, and every piece of AI-generated content in this system reads from the same place: the intelligence layer. If the intelligence layer is thin, generic, or poorly structured, everything downstream will be too. This is not a technical detail — it is the single most consequential architectural decision in the entire operating model.

The research is unambiguous on this point. The organisations that succeed with AI are the ones that invest in knowledge architecture first. The ones that fail skip straight to agents, tools, and automation — and produce generic output that degrades trust. In plain language: the intelligence layer is everything the AI needs to know to sound like 776BC and make decisions like 776BC. It is the brand’s institutional knowledge, structured so that machines can read it and humans can maintain it.

Why the Intelligence Layer Is the Moat

Models are commoditised. GPT, Claude, Gemini — any brand can access the same AI capabilities. The technology is table stakes. What cannot be replicated is accumulated organisational knowledge, deliberately structured for AI consumption. This is the durable competitive advantage.

1. It compounds. Every approved piece of content becomes a new exemplar. Every campaign brief adds to the strategic knowledge base. Every human edit teaches the system what “good” looks like. Over 12 months, a competitor starting from scratch would face thousands of curated knowledge artefacts they cannot replicate.
2. It is brand-specific. A generic AI can write about rowing. Only an AI with 776BC’s intelligence layer can write as 776BC — with Cameron’s voice, the emotive copy framework, the technical authority, and the strategic intent behind every piece.
3. It improves every agent simultaneously. When a new product brief is added to /Brand_Memory/product_knowledge/, every agent — Content Transformer, Podcast Alchemist, Email Composer, Voice Guardian — immediately has access to it. One knowledge update improves ten outputs.
4. It survives technology changes. If a better AI model launches tomorrow, 776BC switches the model and keeps the intelligence layer. The knowledge transfers. The brand memory persists. This is why “memory before agents” is the foundational design principle.
5. It turns knowledge into capability. The intelligence layer is not documentation — it is operationalisation. An essay about “how 776BC writes email copy” is reference material. That same knowledge, structured as an agent skill with input/output contracts, voice parameters, and exemplars, is an executable capability that produces email drafts autonomously.

How to Build It

The intelligence layer build follows a deliberate curation process — not a bulk import. “Dump the PDF into a folder” is the most common failure mode in AI knowledge management. The correct build order matters: knowledge layer before agents, agents before skills, skills before automation. Skip the order and there is no place for knowledge to land.

Phase 1: Foundation (Week 1) — Create the /Brand_Memory/ folder structure. Extract and restructure Voice DNA from the AI Brand Kit into machine-readable format with explicit parameters. Structure the Emotive Copy Framework with annotated examples. Consolidate product knowledge starting with Motion 2.0. Distil the Growth Thesis into a single strategic reference file.
Phase 2: Exemplar Curation (Week 2) — Kate and the team identify 15-20 gold standard content pieces across platforms. Each exemplar is filed with metadata: platform, content pillar, date, voice fidelity notes. Create per-platform guidelines. Consolidate competitive intelligence from Stream A into a living reference.
Phase 3: Validation & Iteration (Weeks 3-4) — Test the intelligence layer: run a content agent against the structured knowledge and evaluate whether the output sounds like 776BC. Kate and Cam review: does this read like us? Where does it fall short? Iterate. This feedback loop is the intelligence layer compounding in real time.

Patterns distilled into canonical brand memory files (voice_dna.md, platform_guidelines/). Compound interest: the intelligence layer gets richer, every agent benefits.
Critical Design Rule
Only curated, validated knowledge gets promoted. The most common failure in AI knowledge management is treating accumulation as progress. Strategic forgetting — archiving or removing low-value content — is a feature, not a bug.
Section 8.2

Mission Control MVP

The full enterprise Mission Control — a custom-built dashboard with Langfuse observability, agent telemetry, and cost tracking — is premature at pilot scale. But operational visibility is not optional. Kate and the team need to see what’s happening in the content pipeline without asking or digging.

Research on production mission control systems — across OpenAI, Anthropic, LangGraph, Temporal, and CrewAI deployments — identifies a clear design principle: mission control must optimise for exception handling and course correction, not constant manual gating. Anthropic’s 2026 analysis of millions of agent interactions found that experienced users allow more autonomy but interrupt more selectively. The implication: the dashboard should draw Kate’s eye to what needs attention, not show her that everything is routine.

Section 9.0

Agent Roles

In this architecture, an “agent” is not a chatbot. It is a folder in the Obsidian vault containing a system prompt, a set of skills, knowledge scope rules, output templates, and few-shot examples. Claude Code reads the configuration and executes accordingly. Each agent has a clear role, an input/output contract, and a defined knowledge scope. Under the Trust Ladder (Section 8.3), each agent begins at Level 1 (Intern) and earns autonomy through demonstrated reliability.

The agents are prioritised by their impact on the velocity gap. The foundation layer (AG-00) coordinates; Tier 1 agents close the velocity gap directly; Tier 2 agents make velocity sustainable; Tier 3 agents add infrastructure when scale demands it. Not every agent needs the frontier model — high-volume, well-defined tasks are candidates for lighter, cheaper models. The pilot will produce the data to validate these assignments.

PGA Tour: reduced article generation costs by 95% using model tiering and prompt caching.
776BC pilot approach: default to Sonnet as primary model for all agents and track where quality requires Opus and where Haiku would suffice. Anthropic’s recommended architecture — Sonnet plans, Haiku executes — is the target operating model.
